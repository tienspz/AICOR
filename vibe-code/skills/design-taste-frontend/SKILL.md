# Design Taste

Make deliberate choices that belong to this product instead of applying a
generic template. Follow the existing stack and preserve real product content.

## Workflow

1. **Read the brief and project.** Identify the audience, primary user goal,
   actual content, framework, existing brand, and available imagery. Inspect
   existing UI before proposing a redesign.
2. **Choose the right design mode.** A page people read and scroll needs a
   clear narrative and meaningful sections. An application screen needs
   efficient scanning, controls, data hierarchy, and predictable states.
3. **Ground the concept in the subject.** Find concrete details from the
   product, its audience, or its domain that can shape the visual direction.
   Do not invent product facts or depend on assets that are not available.
4. **Write a compact design plan before implementation.** State:
   - the core visual idea and why it fits this product;
   - a small named color palette, typography roles, and layout approach;
   - the content hierarchy and the purpose of each section;
   - one memorable visual or interaction, with everything else supporting it.
5. **Challenge defaults.** Check whether the proposed layout, type, colors,
   cards, shadows, labels, and motion are choices made for this brief. Keep a
   familiar pattern only when it serves the user's goal.
6. **Implement within the project.** Reuse the current framework, design
   tokens, and components where appropriate. Avoid unnecessary dependencies,
   placeholder claims, decorative noise, and motion that does not clarify an
   action or hierarchy.
7. **Review the result.** Check responsive behavior, content completeness,
   keyboard focus, contrast, and reduced-motion behavior. Compare the result
   with the plan and remove elements that weaken its central idea. Use browser
   screenshots at desktop and mobile widths when available; say explicitly
   when visual verification was not possible.

For underspecified details, make reasonable assumptions and state them. Ask
only when a missing fact prevents a useful or safe implementation.
